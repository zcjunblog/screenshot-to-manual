# v0.1.0验证报告

日期：2026-11-05；所有示例为虚构数据，截图来自实际运行的本地演示程序。

## 工程与分发

- 完整依赖环境：Python3.12.14、Pillow13.0.0、python-docx1.2.0，51项测试通过。
- 系统Python3.9缺Pillow/Word依赖：doctor明确返回false，ingest退出2并说明缺PIL；标准库环境12项分发测试通过。
- 标准包、WorkBuddy包各自异地解压，从真实截图重新ingest，三组案例validate/render通过，均生成Word；该解压检查关闭PDF，PDF由单独版式验证覆盖。
- Skill标准入口与Codex展示YAML由Ruby Psych解析通过；skill-creator的quick_validate因环境缺PyYAML无法运行，未计作通过。字段/链接/双语示例/独立资源由分发测试和构建工具检查。
- 多客户端目录安装与备份替换已测试；不等于这些客户端都已真实运行本Skill。

## 图像与文档

- 实际运行虚构演示程序并由独立无头Chrome截图，DPR2，提供桌面、手机、混合尺寸三个变体；同一业务流程的尺寸验证，不作为三个行业的语义测试。
- 三份Word/PDF共9页逐页视觉检查；核对中文、截图、裁切、编号、来源与遮盖。首轮发现结果页裁切未完整显示列表，调整示例裁切并重渲染；提高原始截图DPR改善手机局部图清晰度。
- PDF页面数/中文文本回读及Word内嵌图片审计通过；Word只包含派生PNG，移交ZIP不含工作资料、JSON或原图。
- 回归测试包含EXIF归正、透明像素、像素遮盖、源文件变更、同一字节快照、窄裁切、编号与同色边框、相对路径、防覆盖和PDF失败降级。
- 标注数字在图外留白，多个区域使用与编号一致的不同边框颜色；正文仍保留控件原文供核对。
- 新增三套原生Word/PDF模板，同一组混合尺寸截图实际导出office 4页、delivery 5页、training 3页，共12页逐页打开原尺寸PNG检查；表格列宽、图片比例、遮盖、中文、页码与图文对应合格。实际样张在examples/template-previews，记录见template-renders.json。
- 不设置FONTCONFIG_FILE或STM_CJK_FONT、默认LibreOffice启动入口下，三模板PDF中文文本回读通过；training首页由Poppler渲染可读。macOS字体配置只作用本次转换进程，程序未修改系统配置；不据此声称其他系统字体均验证。

## 独立审查

代码审查发现4项可复现问题：透明PNG隐藏颜色显露、missing步骤缺image_id仍校验通过、摘要/读取竞态、窄裁切编号消失。模板聚焦审查另发现Word问题汇总的HTML实体、macOS默认转换缺中文字体；均补失败回归并修复，完整测试通过。另补异常摘要类型、PDF转换失败、转换私有目录和外发白名单路径。

## 真实客户端

WorkBuddy V5.9.3已通过低风险检测并导入0.1.0候选包。DeepSeek-V4.1-Flash从3张原始截图与notes读取、定位、建模并实际导出Word/PDF/ZIP。首轮出现重复步骤偏多与手写图号错位；修订后4步、4页PDF，12项摘要与外发包白名单独立核对通过，仍保留7项缺口。原始输入任务没有提供人工预期模型；记录见workbuddy-baseline.json。

同一客户端随后复用该模型实际生成三套模板：office 5页、delivery 6页、training 5页，Word/PDF均成功，三份Markdown和图片一致，ZIP无内部JSON或转换临时文件。客户端指出training第一步末尾观察文字单独跨页、delivery长标题尾部换行不佳；继续针对实际模型修订分页与标题适配，本地后续记录在client-layout-fix.json。不能把第一次成功导出写成版式已经合格。

测试提供了本机已有Python与LibreOffice路径，未要求客户端自行安装运行环境。包内无这些开发机绝对路径。后续脚本与指引修正同步到已安装目录，候选导入与最终资源更新分开记录，逐文件ZIP匹配见workbuddy-resource-match.json。
